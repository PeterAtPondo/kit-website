Kit's visual identity

This is where Kit's look is decided. Everything in the product, the Lantern, this website, the cards Kit draws inside your editor and the mail it sends is generated from or built on what is here. If a colour, a control or a piece of type disagrees with this folder, this folder is right and the code is wrong.

The two artefacts

The style guide is the whole system on one page: the palette, the type scale, the spacing, and the rules that hold them together.

The component library is the code. A button, a field, a chip, a row, a card, a note, a tile, a drawer, a tab strip, a dot. Every one of them live on the same stylesheet the product uses, so what you see is what ships.

The rules we hold ourselves to

  • Use the library. A new button is a variant of the button we have, not a new one built from utilities.
  • Never declare a colour. No hex anywhere except in the one file that defines what the colours mean.
  • Alpha comes from a scale of six steps. Not a seventh chosen by eye.
  • Colour encodes, it does not decorate. Amber is the accent. Emerald means live, fresh, succeeded, and nothing else. Purple means dreaming. A state colour picked for variety is not allowed.

These are not advice. They run as tests on every build, and they refuse a carrier out of sync, a colour written into a stylesheet, a type size off the scale, or a hand-styled control where a component exists.

One source, five carriers

tokens.json is the vocabulary. Everything else is generated from it: the web interface, this showroom, the MCP cards, the email templates, and the Lantern. Nothing else may declare a palette.
